## 1. 概述

本文档描述了 `AnimePoseDataset` Python 数据对象库的整体设计思路、核心数据结构、类层级关系及使用方式。
该库用于对遵循link-to-anime数据集规范的Mixamo 动漫人物骨骼渲染数据集进行结构化访问，以及将 Mixamo 骨骼格式转换为 COCO-17 关键点格式，并持久化这些数据。
本文档建议您按照该规范构建您的mixamo人物姿态数据集，以便于快速调用各层级数据实例的各种数据和属性，或是将它们扩张、转换为coco规范的数据。

### 1.1 link-to-anime简介
源数据集（`link-to-anime`）由多套动漫人物模型的 Mixamo 骨骼动画渲染而来，每个模型提供 5 个不同视角，每个视角包含 72 帧渲染图像，并附带三种姿态特征点数据。本项目采用其中的像素级骨骼坐标（`bone_coordinates_pixels`）规范的姿态特征点JSON标注文件。当然，该数据集也包括检测框（`Bounding_Box`）的 JSON 标注文件。

### 1.2 基本设计思路

- 层级化封装。Dataset → Model → View → Frame，与文件目录分层对应
- 尽量采用lazy loading，JSON 缓存按需读取，避免重复 I/O
- TODO：当前支持 Mixamo to COCO-17 转换，接口设计预留扩展空间
- 每帧拥有基于路径确定性生成的 UUID，支持全局随机访问
-


## 2. 数据集目录结构
本节讲解遵循link-to-anime数据集规范的Mixamo 动漫人物骨骼渲染数据集结构，同时也包括两次导出JSON后目录的变化
本库假设数据集根目录（`dataset_root`）具有以下层级结构：

```
dataset_root/
├── train/
│   └── <pack_name>/
│       └── <model_name>_model/
│           ├── 01 visual_view/
│           │   ├── 01_1 Rendering/          # 72 帧渲染图（PNG/JPG）
│           │   ├── 01_9 bone_coordinates_pixels.json
│           │   └── 01_10 Bounding_Box.json
│           ├── 02 visual_view/
│           ├── 03 visual_view/
│           ├── 04 visual_view/
│           └── 05 visual_view/
├── val/
└── test/
```

**目录命名规则：**

| 层级       | 命名规则                      | 示例                       |
| -------- | ------------------------- | ------------------------ |
| split    | 固定值                       | `train` / `val` / `test` |
| pack     | 任意目录名                     | `pack_A`                 |
| model    | 以 `model` 结尾              | `character_A_model`      |
| view     | 以 `visual_view` 结尾，两位数字前缀 | `01 visual_view`         |
| frame 文件 | 以 `{frame_id:04d}_` 开头    | `0001_render.png`        |

## 3. 类层级

整个数据对象库由 5 个核心类构成，层级关系如下：

```
AnimePoseDataset
    └── AnimeModel          ← iter_models()
            └── AnimeView   ← iter_views()
                    └── AnimeSkeletonData   ← iter_frames() / get_frame(frame_id)
```

`DatasetConfig` 作为共享配置对象，在各层级之间传递。

---

### 3.1 DatasetConfig

冻结的全局配置 `dataclass`，作为所有层级对象的共享配置项，通过 `config` 参数传递，避免硬编码散落各处。

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `frames_per_view` | `72` | 每个视角的帧数 |
| `image_exts` | `(".png", ".jpg", ".jpeg")` | 渲染图扩展名白名单 |
| `source_dataset_name` | `"link-to-anime"` | 源数据集名称，写入每条样本元数据 |
| `default_source_format` | `"mixamo"` | 骨骼格式标识，写入 `source_format` 字段 |

---

### 3.2 AnimePoseDataset

顶层数据集对象，负责扫描整个 `dataset_root` 目录树，构建 `AnimeModel` 列表，并提供全局遍历与 UUID 随机访问接口。

**主要属性：**

- `root : Path` — 数据集根目录路径
- `config : DatasetConfig` — 全局配置对象
- `debug : bool`（默认 `True`）— 是否打印目录扫描调试信息

**核心方法：**

| 方法签名                            | 返回类型                          | 说明                                             |
| ------------------------------- | ----------------------------- | ---------------------------------------------- |
| `iter_models()`                 | `Iterator[AnimeModel]`        | 遍历所有 split 下的 Model                            |
| `get_model(split, pack, model)` | `AnimeModel`                  | 按三元组精确查找 Model                                 |
| `iter_views(split=None)`        | `Iterator[AnimeView]`         | 跨 Model 遍历所有 View，可按 split 过滤                  |
| `iter_frames(split=None)`       | `Iterator[AnimeSkeletonData]` | 跨全局遍历所有单帧样本                                    |
| `build_index()`                 | `dict[str, tuple]`            | 构建 UUID → (split, pack, model, view, frame) 索引 |
| `get_by_uuid(uuid)`             | `AnimeSkeletonData`           | 通过 UUID 随机读取单帧                                 |
| `clear_all_view_caches()`       | `None`                        | 清除所有 View 的 JSON 文件缓存                          |

---

### 3.3 人物模型目录：AnimeModel

对应文件系统中的一个 `<model_name>_model/` 目录。按需扫描旗下所有 `visual_view` 子目录并实例化 `AnimeView`。

**核心方法：**

| 方法签名 | 返回类型 | 说明 |
|----------|----------|------|
| `views()` | `dict[str, AnimeView]` | 获取 `{view_name: AnimeView}` 字典（扫描结果缓存） |
| `get_view(view_name)` | `AnimeView` | 按名称获取特定视角对象 |
| `iter_views()` | `Iterator[AnimeView]` | 逐个遍历所有视角 |
| `iter_frames()` | `Iterator[AnimeSkeletonData]` | 遍历本 Model 下的所有帧 |
| `export_all_views_coco17_jsons(...)` | `None` | 批量导出全部视角的 COCO-17 JSON |

---

### 3.4 视角目录：AnimeView

对应一个 `XX visual_view/` 目录，负责加载该视角的 `bone_coordinates_pixels.json` 和 `Bounding_Box.json`，并按帧封装为 `AnimeSkeletonData`。JSON 数据在首次访问时加载并缓存，调用 `clear_cache()` 可释放。

**关键属性与计算属性：**

| 名称 | 类型 | 说明 |
|------|------|------|
| `view_index` (property) | `int` | 从 `view_name` 解析出的数字编号，如 `'01 visual_view'` → `1` |
| `prefix` (property) | `str` | 两位数字前缀字符串，如 `'01'`，用于构建子路径 |
| `view_path` (property) | `Path` | `model_path / view_name` 的完整路径 |
| `rendering_dir` (property) | `Path` | `{prefix}_1 Rendering/` 渲染帧目录 |
| `bone_pixels_json_path` (property) | `Path` | `{prefix}_9 bone_coordinates_pixels.json` |
| `bbox_json_path` (property) | `Path` | `{prefix}_10 Bounding_Box.json` |

**核心方法：**

| 方法签名 | 返回类型 | 说明 |
|----------|----------|------|
| `get_frame(frame_id)` | `AnimeSkeletonData` | 读取单帧，封装为 `AnimeSkeletonData` |
| `iter_frames()` | `Iterator[AnimeSkeletonData]` | 生成器，逐帧 yield frame 1~72 |
| `get_frame_bbox(frame_id)` | `Optional[list[float]]` | 查询该帧的边界框 |
| `get_frame_mixamo_keypoints(frame_id)` | `dict[str, dict]` | 获取标准化后的 Mixamo 骨骼点坐标 |
| `get_frame_image_size(frame_id)` | `Optional[tuple[int,int]]` | 用 PIL 读取帧的 `(width, height)` |
| `export_coco17_jsons(face5_provider)` | `None` | 导出本视角所有帧的 COCO-17 JSON |
| `clear_cache()` | `None` | 清除 `bone_pixels` 与 `bbox` 的内存缓存 |

---

### 3.5 帧文件：AnimeSkeletonData

单帧样本的数据容器（`dataclass`），同时承担 Mixamo to COCO-17 格式转换任务。
是整个库的核心数据单元，包含身份信息、路径信息、骨骼关键点、边界框及导出工具方法。

#### 字段分组

**身份与索引字段：**

| 字段名               | 类型    | 说明                                         |
| ----------------- | ----- | ------------------------------------------ |
| `uuid`            | `str` | UUID5，基于 `sample_key` 确定性生成，全局唯一           |
| `sample_key`      | `str` | 人类可读路径键：`split/pack/model/view/frame_XXXX` |
| `split`           | `str` | 数据集划分：`train` / `val` / `test`             |
| `pack_name`       | `str` | 数据包名称                                      |
| `model_name`      | `str` | 模型名称                                       |
| `view_name`       | `str` | 视角目录名，如 `'01 visual_view'`                 |
| `view_index`      | `int` | 视角数字编号                                     |
| `frame_id`        | `int` | 帧编号，1 起始                                   |
| `frames_per_view` | `int` | 该视角总帧数（配置值，默认 72）                          |

**内容字段：**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `image_path` | `str` | 相对 `dataset_root` 的渲染图 POSIX 路径 |
| `keypoints` | `dict[str, dict]` | 骨骼关键点字典，键为骨骼名，值含 `x/y/z/visibility` |
| `bbox` | `Optional[list[float]]` | 检测框 `[x, y, w, h]` 或 `None` |
| `pose_format` | `str` | `'mixamo'` 或 `'coco17'`，标记当前关键点格式 |
| `source_format` | `str` | 来源格式标识 |
| `source_dataset` | `str` | 来源数据集名称 |
| `image_size` | `Optional[tuple[int,int]]` | 图像宽高 `(w, h)`，可能为 `None` |
| `num_keypoints` | `Optional[int]` | `visibility > 0` 的关键点计数 |
| `face5_info` | `Optional[str]` | 面部5点推理状态说明（COCO-17 格式专用） |
| `strict` | `Optional[bool]` | 保留字段（当前版本已弃用，固定为 `None`） |
| `extra` | `dict[str, Any]` | 额外自定义字段，保存到 JSON 时自动展开至顶层 |

**导出路径字段（`repr=False`，不参与序列化）：**
为了直接访问扩张、转换后持久化为json存储的骨骼、bbox等信息，设计这两个属性：
- `json_out_path : Optional[Path]` — Mixamo 格式 JSON 输出路径（由 `AnimeView.get_frame()` 自动填充）
- `coco_json_out_path : Optional[Path]` — COCO-17 格式 JSON 输出路径（由 `AnimeView.get_frame()` 自动填充）

#### 导出方法

| 方法签名                                              | 说明                                                                      |
| ------------------------------------------------- | ----------------------------------------------------------------------- |
| `to_keypoints_flat(order)`                        | 按 `order` 列表展平关键点为遵循                 规范的 `[x1,y1,v1, x2,y2,v2, ...]` 格式 |
| `count_visible_keypoints(order=None)`             | 统计 `visibility > 0` 的关键点个数，`order=None` 时统计全部                           |
| `to_intermediate_dict()`                          | 生成包含所有字段的 Python 字典，供 `json.dump` 使用                                    |
| `save_json(out_path, keypoint_order, indent)`     | 写入 JSON 文件，若提供 `keypoint_order` 则附加 `keypoints_flat` 字段                 |
| `to_coco17(strict, face5_provider, dataset_root)` | 将 Mixamo 格式转换为 COCO-17，返回新的 `AnimeSkeletonData` 实例                      |

## 4. 关键点格式规范

### 4.1 统一关键点结构

所有关键点（无论来源格式）统一用以下字典表示，由 `ensure_standard_keypoint()` 函数保证：

| 键            | 类型      | 说明                           |
| ------------ | ------- | ---------------------------- |
| `x`          | `float` | 像素 x 坐标（水平方向，从左到右）           |
| `y`          | `float` | 像素 y 坐标（垂直方向，从上到下）           |
| `z`          | `float` | 深度值（像素空间 z，Mixamo 相机空间）      |
| `visibility` | `int`   | `0` = 不可见/无效，`2` = 完全可见且在画面内 |

### 4.2 Mixamo-COCO-17 映射

原始数据提供 Mixamo 全身骨骼的像素坐标（`bone_coordinates_pixels.json`）。映射到 COCO-17 时使用的身体12点对应关系如下：

| COCO-17 名称                                           | Mixamo 骨骼名               | 类别                    |
| ---------------------------------------------------- | ------------------------ | --------------------- |
| `left_shoulder`                                      | `mixamorig:LeftArm`      | 身体                    |
| `right_shoulder`                                     | `mixamorig:RightArm`     | 身体                    |
| `left_elbow`                                         | `mixamorig:LeftForeArm`  | 身体                    |
| `right_elbow`                                        | `mixamorig:RightForeArm` | 身体                    |
| `left_wrist`                                         | `mixamorig:LeftHand`     | 身体                    |
| `right_wrist`                                        | `mixamorig:RightHand`    | 身体                    |
| `left_hip`                                           | `mixamorig:LeftUpLeg`    | 身体                    |
| `right_hip`                                          | `mixamorig:RightUpLeg`   | 身体                    |
| `left_knee`                                          | `mixamorig:LeftLeg`      | 身体                    |
| `right_knee`                                         | `mixamorig:RightLeg`     | 身体                    |
| `left_ankle`                                         | `mixamorig:LeftFoot`     | 身体                    |
| `right_ankle`                                        | `mixamorig:RightFoot`    | 身体                    |
| `neck`                                               | `mixamorig:Neck`         | 辅助（不进 `COCO17_ORDER`） |
| `nose / left_eye / right_eye / left_ear / right_ear` | （RTMLib 推理）              | 面部5点；face5            |

### 4.3 COCO-17 顺序、Visibility 规则

转换后的 COCO-17 关键点严格按以下顺序排列（对应 `to_keypoints_flat()` 输出）：

```
nose, left_eye, right_eye, left_ear, right_ear,
left_shoulder, right_shoulder, left_elbow, right_elbow,
left_wrist, right_wrist, left_hip, right_hip,
left_knee, right_knee, left_ankle, right_ankle
```

**Visibility 赋值规则：**

- **身体12点**：坐标来自 Mixamo；若像素点在 `image_size` 范围内则 `visibility=2`，画面外则 `visibility=0`
- **面部5点**：由 `Face5Provider` **推理**；成功且在画面内则 `visibility=2`，推理跳过或失败则 `visibility=0`
- `image_size` 为 `None` 时，跳过画面范围检查，默认视为在画面内

## 5. 基于UUID 与 sample_key的标识系统

### 5.1 sample_key

`sample_key` 是每帧样本的人类可读唯一路径标识，格式为：

```
{split}/{pack_name}/{model_name}/{view_name}/frame_{frame_id:04d}
```

示例：`train/pack_A/hero_model/01 visual_view/frame_0023`

### 5.2 UUID（uuid5）

UUID 通过 `uuid.uuid5(uuid.NAMESPACE_URL, sample_key)` 生成，具有以下特性：

- **确定性**：相同路径始终得到相同 UUID，无需持久化存储
- **全局唯一**：在整个数据集范围内不会碰撞（概率意义上）
- **用途**：`build_index()` 构建的全局索引以 UUID 为键，支持 O(1) 随机访问

### 5.3 UUID 索引

调用 `dataset.build_index()` 后，`_uuid_index` 缓存结构为：

```python
dict[uuid_str, (split, pack_name, model_name, view_name, frame_id)]
```

后续调用 `get_by_uuid()` 时直接查表，无需遍历，适合大规模随机采样训练场景。

> **注意**：`build_index()` 会遍历全部帧（`O(N_model × N_view × N_frame)`），首次调用耗时较长，建议在程序启动阶段提前调用。

## 6. Mixamo to COCO-17 转换流程

`to_coco17()` 方法将 `pose_format='mixamo'` 的 `AnimeSkeletonData` 转换为 COCO-17 格式。

### 6.1 流程步骤

1. **前置检查**：确认 `pose_format == 'mixamo'`，否则抛出 `ValueError`
2. **加载图像**：通过 `dataset_root / image_path` 定位原始渲染图，用 PIL 转为 RGB numpy 数组
3. **面部5点推理**：调用 `face5_provider.infer(img_rgb, mixamo_pixels)`，获取 `Face5Result`
4. **构建 `coco_kps` 字典**：
   - 面部5点：推理成功则取坐标；失败/跳过则补零（`visibility=0`）
   - 身体12点：从 `MIXAMO_TO_COCO17_BODY` 映射表读取对应 Mixamo 骨骼坐标
   - Visibility 根据像素坐标是否在 `image_size` 范围内赋值 `2` 或 `0`
5. **按 `COCO17_ORDER` 排列**，缺失点补零
6. **统计 `num_keypoints`**（`visibility > 0` 的计数）
7. **返回新的 `AnimeSkeletonData` 实例**（`pose_format='coco17'`，`face5_info` 记录推理状态）

### 6.2 补全面部特征点：Face5Provider的接口约定

`Face5Provider` 是一个外部依赖对象（在`face5_provider.py`），`to_coco17()` 方法将其作为必选参数传入。该对象接口约定：

```python
class Face5Provider:
    def infer(
        self,
        img_rgb: np.ndarray,
        mixamo_pixels: dict,
    ) -> Face5Result: ...
```

**`Face5Result` 属性：**

| 属性        | 类型                | 说明                         |
| --------- | ----------------- | -------------------------- |
| `skipped` | `bool`            | `True` 表示推理被跳过（如头部超出画面等原因） |
| `face5`   | `dict[str, dict]` | 面部5点坐标字典，键为关键点名，值含 `x/y`   |
| `reason`  | `str`             | 推理状态说明，写入 `face5_info` 字段  |

## 8. 数据集规范约束

### 8.1 延迟加载与内存管理

- `bone_pixels` 和 `bbox` 的 JSON 文件在首次访问时加载并缓存在 `AnimeView` 实例内
- 处理大型数据集时，若内存受限，可在批量处理完每个视角后调用 `view.clear_cache()` 释放缓存
- `clear_all_view_caches()` 可一次性清除所有已扫描 View 的缓存

### 8.2 frame_id 从 1 开始

所有帧编号从 1 开始（inclusive），至 `frames_per_view`（默认 72）。传入 `0` 或超出范围的值将触发 `ValueError`。

### 8.3 bbox 键名格式

`bbox` JSON 文件中，每帧的键名格式为 `{frame_id:04d}_{view_index}`，例如 `'0023_1'`。若键不存在则返回 `None`。

### 8.4 pose_format 与 strict 字段

- `pose_format` 是格式标记字段，取值 `'mixamo'` 或 `'coco17'`，明确标识当前关键点格式
- `strict` 字段在历史版本中曾用于控制严格模式，当前版本已弃用，固定为 `None`

### 8.5 to_coco17() 不修改原对象

`to_coco17()` 返回全新的 `AnimeSkeletonData` 实例，原始 Mixamo 格式对象保持不变。UUID 和 `sample_key` 在新对象中保持相同，便于关联。

### 8.6 extra 字段

`AnimeSkeletonData` 的 `extra` 字段是一个自由扩展字典，其内容在 `to_intermediate_dict()` 时通过 `dict.update()` 展开到顶层，便于附加自定义元数据（如渲染参数、标注来源等）。
